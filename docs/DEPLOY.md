# Deploying for free: Render (backend) + Neon (Postgres) + Vercel (dashboard)

All three have free tiers that need no card at the time of writing (check
when you sign up — terms change). Railway (`railway.json`) and Fly
(`fly.toml`) configs are kept for anyone who prefers a paid host.

## 1. Database: Neon

1. Sign up at neon.tech (GitHub sign-in works) → **Create project**.
2. Copy the **connection string** (it looks like
   `postgresql://user:…@ep-….neon.tech/neondb?sslmode=require`).
   Keep it to yourself — you will paste it into Render, nowhere else.

The backend accepts it as-is: `postgres(ql)://` becomes the async driver and
`sslmode=require` becomes the driver's SSL setting.

## 2. Backend: Render

1. Sign up at render.com with GitHub → **New → Blueprint** → choose this
   repository. Render reads `render.yaml` (one free Docker web service).
2. It asks for the variables marked secret:
   * `DATABASE_URL` — the Neon connection string
   * `GEMINI_API_KEY` — optional, enables output review and the supervisor chat
   * `CORS_ORIGINS` — leave as `https://placeholder.invalid` for now; set after step 3
   `SECRET_KEY` is generated by Render.
3. Deploy. Open `https://<service>.onrender.com/health` — it should say
   `"status":"ok"` and `"keepalive": {"enabled": true, …}`.

### Keeping it awake (free tier sleeps after ~15 min idle)

* The backend pings its own public URL every 10 minutes while running
  (`RENDER_EXTERNAL_URL` is set by Render; nothing to configure).
* After a redeploy or a platform restart it cannot wake itself, so GitHub
  Actions pings it every 10 minutes too: repository **Settings → Secrets and
  variables → Actions → Variables → New variable**
  `KEEPALIVE_URL = https://<service>.onrender.com`.
* If it is asleep anyway, the dashboard shows "Waking the supervisor" and
  agents keep working — adapters fail open and queue their events.

One always-on free service uses about 730 of Render's 750 free instance hours
a month, so keep only this one service on the free plan in the workspace.

## 3. Dashboard: Vercel

1. Sign up at vercel.com with GitHub → **Add New → Project** → import this
   repository.
2. **Root Directory:** `dashboard`. Framework: Next.js (auto-detected).
3. **Environment variable:** `NEXT_PUBLIC_RELIABILITY_API_URL` =
   `https://<service>.onrender.com` (no trailing slash). Never set
   `NEXT_PUBLIC_RELIABILITY_TOKEN` on a deployment — `NEXT_PUBLIC_` values
   are visible to every visitor.
4. Deploy. Then set the backend's `CORS_ORIGINS` on Render to the Vercel URL
   (e.g. `https://klaw.vercel.app`) — Render redeploys automatically.

## 4. First sign-in and agents

Open the Vercel URL → **Create account** (each account is its own
workspace). Then **Integrations** → create a key → run the one command shown.
Once your accounts exist, set `ALLOW_SIGNUP=false` on Render if the
deployment should be private.

## Notes

* One backend instance (the in-process event bus does not fan out across
  instances). For more, add Redis and set `EVENT_BUS=redis`, `REDIS_URL`.
* Schema changes use `create_all`; add Alembic before upgrading a database
  that holds data you need.
* Render's free instance has 512 MB of memory; the backend uses well under that.
